## 2024-06-25 - Expensive Operations in Sort Comparators
**Learning:** Calling functions that do string formatting or allocate objects inside a `sort` callback's unconditionally executed preamble forces O(N log N) executions of those expensive operations, even if the user isn't sorting by that specific field. Additionally, re-creating arrays inside a sort comparator or filter map creates unnecessary GC pressure.
**Action:** Always conditionally execute expensive derivations inside the sort logic (e.g. inside `switch (sortField) { case 'title': ... }`) instead of at the top of the comparator. Replace `array.indexOf()` lookups with predefined dictionaries/maps (`{ "VALUE": 1 }`) outside the callback for O(1) performance.
